# Записка о дизайне

Space Team Genesis — воспроизводимая офлайн RL-среда для ИИ-аудитора. Мы сдаём не агента, а среду: генератор синтетических компаний со скрытыми ошибками, контракт `reset/step`, изолированный оценщик и награду, которую нельзя получить угадыванием, повтором или массовыми обвинениями. Подробности — в отдельных документах; здесь устройство целиком на двух страницах.

## Как устроено

```
seed, config ──► генератор ──► открытые записи ──► среда reset/step ◄──► агент (5 действий, 100 шагов, 60 с)
                    │                                   │ submit
                    └──► эталон (truth, provenance) ──► оценщик в отдельном процессе ──► награда
```

## Решения, на которых держится оценка

**Ошибка — это записанное изменение, а не подозрительная строка.** Генератор сначала строит согласованную историю (курсы на каждый день, счета, оплаты, расходы), затем вносит ошибки как явные изменения и проводит две книги одним кодом: чистую и опубликованную. Сумма в эталоне — их разница. Четыре типа ошибок настраиваются отдельно, есть два сценария переплетённых ошибок и шесть видов законных «подозрительных» случаев: повторы сумм, переплаты с возвратом, разбитые и групповые платежи, счета прошлого периода, документы у границы периода в чужом часовом поясе.

**Доказательства всегда доступны.** Для каждой ошибки эталон хранит наборы открытых записей, из которых сумма пересчитывается без генератора. `verify.py` проверяет это на каждом эпизоде, а аудитор, видящий только открытые данные, обязан найти ровно эталон. Противоречивых или нерешаемых эпизодов в наборе нет.

**Эталон не утекает.** Агент видит записи только через пять действий. Эталон и seed живут в дочернем процессе оценщика; в closed-режиме публичная награда всегда 0; ошибки фиксированы и не зависят от эталона. В открытых файлах, траекториях и наблюдениях нет полей эталона — это проверяют тесты.

**Награда требует сути, а не текста.** Вывод засчитывается при точном совпадении типа, набора записей, суммы (допуск 0), валюты и полного набора доказательств; сопоставление взаимно однозначное (максимальное паросочетание). Повтор — ложный вывод, объяснение на счёт не влияет. Награда — общая формула кейса `clip(2·F1 − 1 − 0,002·шаги, −1, 1)`.

**Воспроизводимость.** Один `(seed, config, version)` даёт побайтово одинаковые файлы и переходы; смена ID и порядка записей сохраняет ответ oracle и награду. На данные влияют только профиль, размер и разрешённые типы, не режим оценки.

## Измеренный разбор сбоев

20 открытых эпизодов (81 ошибка, 4 чистые компании). Числа — найдено/всего по типу; команда `python -m auditgym.analysis` воспроизводит таблицу.

| Политика | дубли | распределение | курс | период | Чистые книги без обвинений | Ложных выводов | F1 | Награда |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Случайный исследователь | 0/16 | 0/27 | 0/22 | 0/16 | 4/4 | 0 | 0.200 | −0.603 |
| «Пометить всё» | 0/16 | 0/27 | 0/22 | 0/16 | 0/4 | 600 | 0.000 | −1.000 |
| Простая сверка | 16/16 | 0/27 | 0/22 | 0/16 | 4/4 | 0 | 0.442 | −0.148 |
| Внимательный аудитор | 16/16 | 27/27 | 22/22 | 16/16 | 4/4 | 0 | 1.000 | +0.959 |

Что это показывает:

- **Простая сверка** находит все дубли, но не видит ни одной ошибки распределения, курса и периода: для них нужно применить учётную политику (дата курса по времени компании, порядок погашения, границы периода), а не сравнивать суммы. Отсюда F1 0,44 и отрицательная награда.
- **«Пометить всё»** получает 600 ложных обвинений и −1 на каждом эпизоде: массовые обвинения не окупаются.
- **Случайный исследователь** получает F1 = 1 только на чистых книгах, где пустой ответ верен, поэтому средний F1 = 0,2.
- **Внимательный аудитор** работает только с открытыми записями и находит все 81 ошибку без ложных выводов: задача решаема по доказательствам. От предела награды его отделяет только цена шагов (~20 шагов чтения).
- Oracle (только внутри оценщика) даёт 1,0 и задаёт предел награды, а не способность агента.

## Как проверить

```bash
make check     # тесты, проверка 20 эпизодов, интеграционный прогон
make report    # P/R/F1, награда, шаги, время четырёх политик в изолированном оценщике
python -m auditgym.analysis                       # разбор сбоев по типам
python -m auditgym.analysis --trajectories trajectories   # публичные траектории
make site      # сайт, песочница и API на 127.0.0.1:8000
```

Траектории: `trajectories/trajectories.jsonl` — простая сверка на 20 открытых эпизодах; `trajectories/by_policy/` — остальные публичные политики на train. Только поля контракта: `episode_id, step, action, observation, reward, terminated, truncated`; режим open, поэтому терминальная награда видна.

## Честные ограничения

- Модель учёта упрощена: только дебиторка, без налогов, кредиторки и переоценки на конец периода. Это синтетическая учебная задача, а не аудиторское заключение.
- Генератор открыт: зная seed, эталон можно воспроизвести. Закрытые seed должны быть случайными 53-битными числами и храниться у оценщика; `GENESIS_EPISODE_KEY` должен быть своим для закрытой проверки.
- Внимательный аудитор доказывает решаемость, но не является обученной моделью; обучение весов мы не заявляем.
- По общей формуле при 5+ ошибках быстрый ответ без одной находки может обойти полный медленный ответ (таблица в [MATCHER.md](MATCHER.md)) — это свойство формулы кейса.
- Лимит 60 секунд одинаков для человека в песочнице и для агента; для ручной игры мы его не ослабляли.
